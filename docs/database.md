# Database — TRIXIA

## Konfigurasi koneksi

API Node.js membuka koneksi PostgreSQL melalui package `pg`. Isi URL pada `DATABASE_URL` di `.env`, atau konfigurasi `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, dan `PGPASSWORD` secara terpisah. Zona waktu backend adalah `Asia/Jakarta`.

Schema PostgreSQL untuk instalasi baru berada di [server/db/schema.sql](../server/db/schema.sql). Jalankan melalui `psql` atau pgAdmin. Backend juga membuat tabel session `user_sessions` secara otomatis.

## Diagram relasi

```text
users 1 ───── 0..n orders
  │                  │
  └── 1 ───── 0..n password_reset_tokens

password_reset_requests berdiri sendiri
```

- `orders.customer_id` nullable dan merujuk `users.id`; penghapusan akun tidak menghapus pesanan.
- `orders.customer_username` adalah snapshot username saat pesanan dibuat.
- `password_reset_tokens` terhapus ketika akun pemiliknya dihapus.
- `password_reset_requests` memakai hash email dan mengatur jeda permintaan, bukan foreign key ke akun.

## Tabel

### `users`

| Kolom | Tipe PostgreSQL | Aturan/kegunaan |
| --- | --- | --- |
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | Primary key, auto increment. |
| `name` | `VARCHAR(120)` | Nama tampilan. |
| `username` | `VARCHAR(30)` | Wajib dan unik; username akun TRIXIA. |
| `email` | `VARCHAR(254)` | Nullable dan unik; salah satu dari email/telepon harus tersedia pada profil. |
| `phone` | `VARCHAR(20)` | Nullable dan unik. |
| `password_hash` | `VARCHAR(255)` | Hash bcrypt, bukan password polos. |
| `created_at` | `TIMESTAMPTZ` | Waktu pembuatan dengan zona waktu. |

### `orders`

| Kolom | Tipe PostgreSQL | Aturan/kegunaan |
| --- | --- | --- |
| `order_key` | `CHAR(32)` | Primary key acak hex 16 byte; dipakai sebagai referensi invoice internal. |
| `order_id` | `INTEGER` | Nomor publik unik enam digit. |
| `customer_id` | `BIGINT` | Nullable; relasi ke akun pembeli, `ON DELETE SET NULL`. |
| `customer_username` | `VARCHAR(30)` | Snapshot username TRIXIA; kosong/null untuk tamu. |
| `game` | `VARCHAR(120)` | Nama produk/game. |
| `nominal` | `VARCHAR(255)` | Label nominal dan harga seperti dikirim frontend. |
| `payment` | `VARCHAR(50)` | Metode pembayaran terpilih. |
| `user_id` | `VARCHAR(120)` | ID akun game tujuan. |
| `server_id` | `VARCHAR(80)` | Server game; default string kosong. |
| `username` | `VARCHAR(120)` | Nickname game bila tersedia; default string kosong. |
| `status` | `VARCHAR(16)` | `Pending`, `Processing`, atau `Success`, dibatasi `CHECK`. |
| `proof_mime` | `VARCHAR(50)` | MIME gambar bukti pembayaran. |
| `proof_data` | `BYTEA` | Biner gambar bukti pembayaran. |
| `created_at` | `TIMESTAMPTZ` | Waktu pembuatan. |

Indeks tambahan: `(status, created_at)` untuk daftar/laporan status dan `created_at` untuk pengurutan periode.

### `password_reset_tokens`

| Kolom | Tipe PostgreSQL | Aturan/kegunaan |
| --- | --- | --- |
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | Primary key, auto increment. |
| `user_id` | `BIGINT` | Foreign key ke `users.id`, `ON DELETE CASCADE`. |
| `token_hash` | `CHAR(64)` | Hash SHA-256 token; unik. Token mentah hanya dikirim ke pengguna. |
| `expires_at` | `TIMESTAMPTZ` | Waktu kedaluwarsa (satu jam setelah dibuat). |
| `used_at` | `TIMESTAMPTZ` | Nullable; token aktif memiliki nilai `NULL`. |
| `created_at` | `TIMESTAMPTZ` | Waktu pembuatan token. |

Indeks: `(user_id, created_at)` dan `expires_at`.

### `password_reset_requests`

| Kolom | Tipe PostgreSQL | Aturan/kegunaan |
| --- | --- | --- |
| `email_hash` | `CHAR(64)` | Primary key SHA-256 email ternormalisasi. |
| `last_requested_at` | `TIMESTAMPTZ` | Waktu permintaan terakhir; endpoint membatasi permintaan berulang selama 60 detik. |

## Migrasi dari MySQL lama

`server/db/schema.sql` membuat struktur PostgreSQL baru, bukan mengimpor data dari database MySQL lama. Backup database lama dan lakukan ekspor/impor data secara terpisah sebelum menghapusnya. Hash password bcrypt yang dibuat PHP dapat diverifikasi oleh backend Node.js.

## Retensi dan operasional

- Bukti gambar berada di PostgreSQL; data dapat memperbesar backup dan penggunaan disk.
- Hapus akun mempertahankan pesanan tetapi menghapus token reset milik akun.
- Penghapusan pesanan dilakukan admin melalui API dan menghapus bukti bersama record-nya.
- Jadwalkan backup database dan uji proses restore secara terpisah.
